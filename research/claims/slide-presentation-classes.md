# Claim: Slide boundary markers own persistent endpoint resources

- ID: `claim.note.slide-presentation-classes`
- State: active
- Maturity: verified
- Confidence: high
- Owner: codex-root
- Coverage rows: `parser.events`, `note.slide`, `state.ownership`; viewer rows
  `model.normalization`, `render.slide`, `render.feedback_layering`, and
  `config.external_presentation`
- Last reviewed: 2026-08-07

## Statement

An ordinary parsed type-2 Slide has a separate root/start resource and three
shared path resources. Each generated segment owns an additional persistent
endpoint resource exactly when its ending boundary marker is set: authored
`SLD`/`SXD` set the marker, `SLC`/`SXC` clear it, and the final segment is
forced set. The root command-form bit, decoded style, and field-9 selector have
separate consumers; field 9 selects result feedback and does not classify the
persistent path or its endpoints.

## Observations

- The four commands store root/control field pairs `SLD=(0,1)`,
  `SXD=(1,1)`, `SLC=(0,0)`, and `SXC=(1,0)`. The first field is retained as a
  root property. The second is copied into generated path-boundary state.
  Continuation does not replace the existing root's first field.
- Field 8 is decoded by the exact `SLD`, `HLD`, `GRN` table and is required by
  the continuation match. Code 1/exact `HLD` is retyped to HeavenHold before
  the type-2 builder, so the presentation behavior below applies only to
  records that remain ordinary Slide.
- Only the extended command forms decode optional field 9. The exact string
  order is `UP`, `DW`, `CE`, `RC`, `LC`, `RS`, `LS`, `BS`; missing, empty,
  differently cased, or unknown values become zero. Common runtime load copies
  this code only when the parsed root's first field is set.
- For every adjacent pair, the builder writes the preceding boundary marker
  to generated byte `+0x34`, the ending marker to `+0x35`, and final-segment
  state to `+0x20`. The root boundary is forced one. Nonfinal ending markers
  retain the authored second field, while the last segment's ending marker is
  forced one. Presentation-record construction initializes result-table index
  `+0x58` to `0xff`.
- Decoded Slide style is bounded to indices 0 through 2 before selecting three
  external shared path-resource descriptors. Their installed primitive
  topology/mode values are 4, 3, and 3. These shared path resources are not the
  per-segment endpoint objects.
- Slide load selects a distinct root/start resource by bounded width and style.
  A clear root command-form field uses the ordinary resource family. A set
  field enters the extended branch, where another runtime byte chooses one of
  two external width-indexed tables. The actual resource identities are not
  chart data and remain excluded.
- The same load walks generated segments and preloads the endpoint resource
  family only for entries whose ending marker `+0x35` is nonzero. The lazy
  allocator repeats that guard: marker zero returns without allocating;
  marker one decodes generated `+0x14`, the ending control's width, then
  selects by that post-boundary width, root style, final-segment byte, and a
  runtime variant. Generated `+0x10` is the preceding/start width and is not
  the endpoint selector. The allocator then stores the resource handle and
  object pointer.
- The presentation update manages the root resource separately. For every
  generated segment it updates the projected/lateral transform and invokes the
  guarded allocator. A present endpoint object is requested visible exactly
  when `!(result_index < byte(loaded_result_table_row_count))`. Consequently
  the initial `0xff` is visible for every byte-sized row count. An in-range
  resolved index hides the object.
- When generated boundary feedback becomes due, the gameplay update stores the
  current mapped result-table index on a marked segment and hardcodes index 4
  on an unmarked segment. Only the marked case can own the persistent endpoint
  resource, so the hardcoded unmarked value has no endpoint-object consumer.
  This state is separate from authored checkpoint result submission.
- On the extended root-result feedback path, runtime field 9 is passed to a
  selector that accepts unsigned indices 0 through 7, chooses one of two
  eight-entry feedback tables by mode, and returns -1 outside that range. The
  consumer starts the selected result-feedback resource. No shared path,
  generated endpoint, projection, or persistent resource selector reads this
  field.
- Cleanup disables and releases the separate root and generated endpoint
  resources without transferring ownership back into parsed chart state.

## Reasoning

The parser's second command field reaches generated `+0x35`; both preload and
lazy allocation independently require that byte; and the presentation update
can access an endpoint object only after that allocation. This closes the
visible-class predicate without relying on command spelling or footage. The
root form, style, and field-9 values each follow disjoint data paths to root
resource, shared path/resource families, and result feedback respectively, so
none can substitute for the endpoint marker.

## Alternatives and falsifiers

- Competing explanation: every control point creates a visible endpoint, or
  field 9/direction determines which controls are visible.
- Evidence that would disprove this claim: an allocation path for marker-zero
  generated entries, a marker-one entry that bypasses allocation despite a
  valid resource table, a persistent geometry consumer of runtime field 9, or
  an ordinary nonfinal builder that overwrites the authored ending marker.

## Unknowns

- Root, shared-path, endpoint, and feedback resource images/materials, their
  player-facing names, shader behavior, and final pixel composition are
  external product data and are intentionally not reconstruction inputs. The
  selection inputs and resource-presence/lifetime predicates are closed.
- The loaded NotesJudgeResultTable row count and rows are external. A
  chart-only unresolved endpoint can use the exact `0xff` state; simulating a
  resolved endpoint requires the explicit loaded count rather than a guess.
- The player-facing name of the runtime byte that chooses between the two
  extended-root resource tables remains unassigned. Both branches and all
  downstream consumers are explicit.
- This claim does not close the resource-independent Slide path mesh, camera,
  submission/layering, or HeavenHold presentation rows.
